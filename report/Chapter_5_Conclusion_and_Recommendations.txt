5.1 Introduction
This chapter presents the conclusions and recommendations drawn from the design, implementation, and testing of the ExamLoc Online Exam Anti-Cheating System. It summarizes the overall project achievements, highlights key outcomes of the system evaluation, provides practical recommendations for deployment, and identifies future research paths to further strengthen online academic integrity.

---

5.2 Summary of the Project
The primary goal of this project was to design and implement a security-sensitive, high-integrity digital examination platform capable of reducing cheating through real-time biometric and behavioral monitoring. To achieve this, the ExamLoc system was developed using a modern, decoupled architecture:
1. Frontend Client: Built with Next.js, hosting the examination interface, managing local hardware access (webcam), capturing visibility and focus events, and disabling unauthorized actions like right-clicks and copy-pasting.
2. Backend API Gateway: Built with FastAPI, acting as a high-performance, asynchronous REST and WebSocket coordinator that handles JWT authentication, exam timing logic, and session state transitions.
3. Asynchronous Worker Queue: Built with Celery and Redis, offloading CPU-intensive face localization, grayscale quality gates, and 128-dimensional biometric embedding calculations.
4. Database & Storage: Built using PostgreSQL for metadata persistence and MinIO (S3-compatible object storage) with local filesystem fallback for security logs and proctoring snapshots.

Through system integration and testing, the platform successfully demonstrated its capability to detect violations (such as tab switching, window focus loss, face absence, and face mismatches) and persist progress in a fault-tolerant manner.

---

5.3 Conclusions
Based on the implementation and testing results presented in Chapter Four, the following conclusions are made:
1. **Asynchronous Architecture Viability**: Offloading biometric verification tasks to a Celery background worker successfully preserved the FastAPI server's responsiveness. The FastAPI endpoints returned immediate queue statuses within 18 ms, while the Celery worker computed HOG face detection and ResNet-34 embeddings asynchronously in 850 ms. This guarantees system scalability under high concurrency.
2. **Optimal Biometric Threshold**: Through experimental evaluation, a Euclidean distance threshold of 0.40 was identified as the optimal balance for identity verification. It minimized user friction by keeping the False Rejection Rate (FRR) at 1.20% while enforcing robust security with a False Acceptance Rate (FAR) of 0.08%.
3. **Robust System Resilience**: The combination of client-side local UI state tracking and an asynchronous auto-save loop successfully guarded against client power and network drops. The system restored candidate answers seamlessly, preventing data loss.
4. **Authoritative Server Security**: Enforcing exam timing restrictions and JWT validations at the database level successfully negated client-side clock tampering and cross-origin token hijacking.
5. **Data Protection Compliance**: The implementation of automated 7-day snapshot deletion and biometric minimization policies (only storing images when a violation is flagged) successfully aligned the system with standard data protection regulations such as GDPR.

---

5.4 Recommendations
For institutions planning to deploy the ExamLoc system for high-stakes examinations, the following recommendations are proposed:
1. **Infrastructure Capacity**: Deploy the FastAPI server, Redis broker, and Celery workers on horizontally scaling VPS environments to handle peak loads during exam commencements.
2. **Standardized Lighting and Hardware**: Candidates should be instructed to take exams in well-lit environments using webcams with a minimum resolution of 720p to prevent rejection by the grayscale luminance and Laplacian variance gates.
3. **Integration with Existing LMS**: The system should be wrapped in an LTI (Learning Tools Interoperability) container to allow single sign-on (SSO) and direct grading sync with Learning Management Systems (LMS) such as Canvas or Moodle.
4. **Data Consent Policy**: Transparent data usage disclosures should be presented to students, obtaining explicit consent for webcam access and biometric verification before enrollment.

---

5.5 Future Work
To further build upon the current system, the following areas are suggested for future development:
1. **Multi-Modal Biometrics**: Incorporate real-time audio analysis and voice activity detection (VAD) to flag background whispers or secondary conversations.
2. **WebRTC Streaming**: Migrate from periodic base64 snapshot posts to a WebRTC-based low-latency video channel, enabling real-time live examiner video proctoring without overloading server resources.
3. **Adaptive Environmental Baselines**: Implement machine learning models that adapt the biometric and behavioral threshold levels dynamically based on initial lighting and background noise baselines.
4. **Gaze Tracking Optimization**: Integrate lightweight client-side gaze estimation using WebGL to track continuous eye movements without relying on external eye-tracking hardware.
